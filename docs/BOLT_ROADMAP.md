# 볼트 체결 강화 — 개발 계획 (2026-11-05)

목표: **볼트로 고정하면서도 회전할 수 있게** 해서 크랭크 동작(크랭크-로커, 크랭크-슬라이더)을 자연스럽게 조립·구동할 수 있게 한다.
(실물에서는 너트를 끝까지 조이면 고정, 덜 조이면 회전하고, 한 볼트에 판이 여러 장 겹쳐 끼워진다. 그 두 가지를 모델에 넣는다.)

## 1. 현재 상태 (코드 기준)

| 체결 | 내용 | 위치 |
|---|---|---|
| `bolt` | 구멍–구멍 고정(강체). B 모드에서 링 클릭 | `main.js` findCandidates / addConnection |
| `pivot` | 구멍–구멍 **회전볼트**. Shift+클릭으로만 생성 | `kinematics.js` JOINT, 폐루프는 구속으로 풀이 |
| `slot` | 장공 안에서 미끄럼 + 회전 | 직선 장공만 지원 |
| `bearing` / `clip` / `drive` | 축↔판, 기어↔축, 모터↔축 | |

이미 되는 것: 4절 링크 1회전(핀 오차 1e-4mm), 크랭크-슬라이더(이론식 오차 0.0000mm).

**빠진 것 / 문제**
1. 체결이 **구멍 한 쌍 단위**다. 한 볼트에 판이 3장 이상 겹치면 쌍마다 후보가 따로 나오고(A–B, B–C, A–C), A–C 는 같은 자리에 중복 구속이 된다.
2. 고정↔회전이 **생성 시점에 정해진다**(Shift 를 눌렀는지). 만든 뒤 바꾸려면 지우고 다시 만들어야 한다. 발견하기도 어렵다(도움말에만 있음).
3. 한 볼트 안에서 "A–B 는 고정, B–C 는 회전"처럼 **층마다 다른 상태**를 못 준다 → 크랭크 핀(크랭크+링크+고정 와셔)을 못 만든다.
4. 볼트 **길이(0.6 / 1.3 / 2 / 3cm)**·너트·와셔·부싱 개념이 없다. 몇 장까지 끼워지는지, 판 사이 간격이 얼마인지 모른다.
5. 크랭크 동작을 보여 줄 **데모 구조물과 회귀 테스트**가 저장소에 없다(검증 스크립트는 임시 폴더에서만 돌렸다).

## 2. 방향 (설계 원칙)

- **볼트를 하나의 객체로 본다.** 구멍 쌍이 아니라 "볼트 1개 = 축선 + 그 축선을 지나는 판들의 순서 있는 목록(스택)".
- **층(인터페이스)마다 상태를 둔다.** 이웃한 두 판 사이를 `fixed`(조임) 또는 `free`(회전) 로. 너트가 어느 층까지 조였는지의 결과로 본다.
- 풀이기(`kinematics.js`)는 건드리지 않는 것이 목표다. 스택을 **기존 `bolt`(강체) / `pivot`(회전) 연결의 묶음으로 풀어서** 넘긴다 → 검증된 풀이 코드를 재사용.
- 기존 저장 파일(`BL1.`)은 계속 열려야 한다. 새 형식은 버전을 올리고 하위호환 변환을 둔다.
- 지금처럼 빌드 단계 없음, 순수 Three.js 유지.

- [ ] 현재 `bolt`/`pivot` 동작을 고정하는 회귀 테스트(생성, 직렬화·복원, 풀이 결과).

### P1. 데이터 모델: 볼트 스택
- [ ] `assembly` 에 `fasteners`(볼트) 컬렉션 추가: `{ id, axis:{p,n}, layers:[{partId, holeIndex}], joints:['fixed'|'free', ...], length }`.
- [ ] 스택 탐지: 같은 축선(반지름 오차 ≤ `COAX_RADIAL`)에서 겹친 구멍들을 축 방향 순서로 묶는다. 판 두께 합으로 접촉 여부 판정.
- [ ] 중복 제거: 스택의 모든 쌍(A–C 등)이 아니라 **이웃 층(A–B, B–C)만** 연결로 만든다.
- [ ] 연결 풀기(`expand`): 스택 → 기존 `bolt`/`pivot` 연결 목록. 풀이기와 `componentOf` 는 이 결과만 본다.
- [ ] `preset.js` 버전 올림(`PRESET_VERSION`), `fasteners` 직렬화 + 구버전 `bolt`/`pivot` 연결을 2장짜리 스택으로 변환.
- 완료 기준: 구형 저장 코드를 열면 동일한 구조물이 복원되고 풀이 결과가 같다.

### P2. 고정 ↔ 회전 전환
- [ ] 이미 만든 체결의 상태를 **바꾸는** 동작: 링 클릭 = 고정→회전→해제 순환(또는 우클릭 메뉴). Shift+클릭 의존을 없앤다.
- [ ] 스택 층별 토글: 층 사이(판과 판 사이)를 눌러 그 층만 전환. 색: 고정=노랑, 회전=주황(지금 색 유지).
- [ ] 시뮬 중에는 전환 금지(편집 모드에서만), 전환 시 `pushUndo`.
- [ ] 상태 문구와 도움말 갱신("조임/풀림" 용어 통일).
- 완료 기준: 3장 스택에서 A–B 고정 + B–C 회전을 만들고, 시뮬에서 C 만 B 에 대해 돈다.

### P3. 볼트·너트·와셔 사양 (현실감)
- [ ] 볼트 길이 종류(0.6 / 1.3 / 2 / 3cm, 부품 목록 41·65·66·67)와 너트(42)·와셔(43·44)·조정부싱(52) 모델링은 **선택 사항**으로 단계 도입:
  1. 길이 검증만: 스택 두께 합 > 볼트 길이 − 너트 두께면 경고(차단 아님).
  2. 와셔·부싱이 층 사이 간격을 만드는 것.
  3. 볼트 메시를 길이에 맞게 그리기.
- 완료 기준: 두꺼운 스택에 짧은 볼트를 쓰면 경고가 뜬다.

### P4. 크랭크 동작 완성

- [ ] 데모 구조물 2종을 프리셋 코드로 저장소에 넣는다(`examples/`): 크랭크-로커, 크랭크-슬라이더(장공 피스톤).
- [ ] 잠김(그라쇼프 조건 위반) 진단 문구 개선: 어느 링크가 문제인지 표시.

## 5. 위험
- 스택을 풀어서 넘기면 같은 축선에 **여러 회전 조인트가 겹쳐** 풀이기가 중복 구속으로 느려지거나 잠길 수 있다 → P1 에서 이웃 층만 연결하고, 회전 층이 연속이면 한 조인트로 병합하는 최적화를 검토.
- 구버전 저장 파일 호환 — 변환 테스트를 P1 에 포함.
- 곡선 장공은 장공 조인트로 못 쓴다(별도 과제).
